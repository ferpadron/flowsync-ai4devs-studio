## Project overview

FlowSync is a team task-management app used as a training project (LIDR academy AI4Devs course). It's a monorepo with two independent, separately-run apps:

- `backend/` — API built with AdonisJS 7 (Node/TypeScript), SQLite via Lucid ORM.
- `frontend/` — React 19 + Vite + TypeScript. Currently the unmodified Vite/React starter template (no router or state library added yet) — treat existing `App.tsx`/CSS as scaffolding to be replaced, not a pattern to preserve.

The repo tracks sprint branches (`s1/start`, `s1/end`, `s2/start`, ... on the `upstream` remote) corresponding to course modules.

## Commands

### Backend (`cd backend`)

```bash
npm install
cp .env.example .env
node ace generate:key      # sets APP_KEY in .env
node ace migration:run     # creates tmp/db.sqlite3 and applies migrations
npm run dev                # serves with HMR at http://localhost:3333
npm run build               # ace build (production build)
npm start                   # run built server (node bin/server.js)
npm test                    # node ace test — runs all Japa suites
npm run lint                 # eslint .
npm run format                # prettier --write .
npm run typecheck              # tsc --noEmit
```

Run a single test file or suite with Japa filters, e.g.:
```bash
node ace test --files="tests/functional/auth.spec.ts"
node ace test unit          # run only the "unit" suite
node ace test functional    # run only the "functional" suite
```

Other useful `ace` commands: `node ace make:controller`, `node ace make:migration <name>`, `node ace make:validator`, `node ace migration:rollback`, `node ace repl`.

### Frontend (`cd frontend`)

```bash
npm install
npm run dev        # Vite dev server at http://localhost:5173
npm run build       # tsc -b && vite build
npm run lint          # oxlint
npm run preview        # preview production build
```

Run backend and frontend in separate terminals; the frontend expects the API at `http://localhost:3333` (configure CORS via `CORS_ORIGIN` in `backend/.env` if needed).

## Backend architecture

AdonisJS uses **subpath imports** (defined in `backend/package.json` `imports`) instead of relative paths across the app, e.g. `#models/*`, `#controllers/*`, `#services/*`, `#validators/*`, `#middleware/*`, `#database/*`, `#start/*`, `#config/*`. Always use these aliases rather than relative imports when adding files under `app/`.

Request flow: `start/routes.ts` → controller (`app/controllers/`) → validator (`app/validators/`, built with VineJS `vine.create(...)`) → Lucid model (`app/models/`) → transformer (`app/transformers/`, extends `BaseTransformer`) → serialized response.

- Routes are grouped under `/api/v1`, with `auth` (signup/login, unauthenticated) and `account` (profile/logout, behind `middleware.auth()`) sub-groups. See `backend/start/routes.ts`.
- Auth has two guards configured in `config/auth.ts`: `api` (token-based, `DbAccessTokensProvider`, **default**) and `web` (session-based, available but not currently used by routes). Access tokens are managed via `User.accessTokens` on the `User` model.
- **Custom response serialization**: `providers/api_provider.ts` registers `ctx.serialize()` / `ctx.serialize.withoutWrapping()` on `HttpContext`, wrapping all JSON responses in `{ data: ... }`. Controllers call `return serialize(...)` rather than returning raw objects — follow this convention for new endpoints.
- **`database/schema.ts` is auto-generated** from migrations (Lucid's `schemaGeneration` in `config/database.ts`) — it's regenerated by `node ace migration:run`/`migration:rollback`. Never hand-edit it. Models compose these generated schema classes (see `app/models/user.ts extends compose(UserSchema, withAuthFinder(hash))`) and add behavior/getters on top rather than redeclaring columns.
- **Tuyau** (`@tuyau/core`) auto-generates a typed route registry under `backend/.adonisjs/client/` (via the `generateRegistry()` hook in `adonisrc.ts`) from the routes file, intended to give the frontend an end-to-end typed API client. This regenerates automatically on `ace` commands (dev/build/test) — don't hand-edit `.adonisjs/`.
- Middleware stack (`start/kernel.ts`): server-level (`force_json_response`, `container_bindings`, CORS) runs on every request; router-level (bodyparser, session, shield, auth init, silent auth) runs on matched routes. The named `auth` middleware supports per-route guard overrides via `middleware.auth({ guards: [...] })`.
- DB: SQLite file at `backend/tmp/db.sqlite3` (git-ignored, created by migrations). Config in `config/database.ts` also has commented-out Postgres/MySQL/MSSQL/libSQL connection stubs if the project needs to switch engines.
- Tests use Japa (`backend/tests/bootstrap.ts` wires `assert`, `apiClient`, `authApiClient`, `sessionApiClient`, `dbAssertions`, `pluginAdonisJS`). Suites are defined in `adonisrc.ts`: `unit` (`tests/unit/**`) and `functional` (`tests/functional/**`, boots the HTTP server via `testUtils.httpServer().start()`). Neither directory has spec files yet.


## Reglas de proceso
- Antes de tocar código: crear una rama nueva (`git checkout -b feat/<slug>`). Nunca commitear directo en `main`/`s1/start`.
- Al cerrar la tarea: usar la skill `/commit`, luego `gh pr create` con una descripción completa de los cambios en el cuerpo del PR.
- Después de abrir el PR: usar el subagente `adversarial-reviewer` sobre él, antes de darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo con la URL del PR.
